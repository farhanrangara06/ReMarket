# ReMarket — Cloud Deployment Guide

Deploy ReMarket to production using **MongoDB Atlas** (database), **Render** (API), and **Vercel** (frontend).

```
┌─────────────┐     HTTPS      ┌──────────────┐     HTTPS      ┌─────────────────┐
│   Vercel    │ ──────────────▶│    Render    │ ──────────────▶│  MongoDB Atlas  │
│  (React)    │   API calls    │  (Express)   │   queries      │   (Database)    │
└─────────────┘                └──────────────┘                └─────────────────┘
                                      │
                                      ▼
                               ┌──────────────┐
                               │  Cloudinary  │
                               │   (Images)   │
                               └──────────────┘
```

**Estimated time:** 30–45 minutes  
**Cost:** Free tier available on all three platforms (with limits).

---

## Prerequisites

- GitHub account with this repo pushed
- [MongoDB Atlas](https://www.mongodb.com/atlas) account (free)
- [Render](https://render.com) account (free)
- [Vercel](https://vercel.com) account (free)
- [Cloudinary](https://cloudinary.com) account (free — required for images on Render)
- Gmail App Password for SMTP (Phase 4 email)

---

## Step 1 — MongoDB Atlas

1. Go to [cloud.mongodb.com](https://cloud.mongodb.com) → **Create** → **MONGODB FREE**.
2. Choose a cloud provider/region (e.g. AWS Mumbai `ap-south-1`).
3. Create a database user:
   - **Database Access** → **Add New Database User**
   - Username + strong password (save these)
4. Allow network access:
   - **Network Access** → **Add IP Address** → **Allow Access from Anywhere** (`0.0.0.0/0`)
   - Required for Render's dynamic IPs on the free tier
5. Get connection string:
   - **Database** → **Connect** → **Drivers**
   - Copy: `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/remarket?retryWrites=true&w=majority`
   - Replace `<password>` with your actual password (URL-encode special characters)

---

## Step 2 — Cloudinary (images)

Render's filesystem is ephemeral — uploaded images are lost on restart. Use Cloudinary in production.

1. Sign up at [cloudinary.com](https://cloudinary.com).
2. From the dashboard, copy:
   - **Cloud name**
   - **API Key**
   - **API Secret**

---

## Step 3 — Deploy API on Render

### Option A — Blueprint (recommended)

1. Push this repo to GitHub.
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
3. Connect your GitHub repo — Render reads `render.yaml` automatically.
4. Set these env vars when prompted (or later in **Environment**):

| Variable | Value |
|----------|-------|
| `MONGO_URI` | Your Atlas connection string |
| `CLIENT_URL` | `https://your-app.vercel.app` (update after Step 4) |
| `CLOUDINARY_CLOUD_NAME` | From Cloudinary dashboard |
| `CLOUDINARY_API_KEY` | From Cloudinary dashboard |
| `CLOUDINARY_API_SECRET` | From Cloudinary dashboard |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_USER` | Your Gmail |
| `SMTP_PASS` | Gmail App Password |
| `EMAIL_FROM` | Same as SMTP_USER or `noreply@yourdomain.com` |

`JWT_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by the blueprint.

5. Click **Apply** — deploy takes ~3–5 minutes.
6. Note your API URL: `https://remarket-api.onrender.com` (or your chosen name).

### Option B — Manual Web Service

1. **New** → **Web Service** → connect repo.
2. Settings:
   - **Root Directory:** `server`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/api/health`
3. Add all env vars from `server/.env.production.example`.

### Verify API

```bash
curl https://remarket-api.onrender.com/api/health
```

Expected response:
```json
{
  "success": true,
  "message": "ReMarket API is running",
  "environment": "production",
  "storage": "cloudinary",
  "email": "smtp",
  "database": "connected"
}
```

### Seed production database (optional)

From your local machine with production `MONGO_URI`:

```bash
cd server
# Temporarily set MONGO_URI to Atlas connection string in .env
npm run seed
```

## Step 4 — Deploy Frontend on Vercel

1. Go to [vercel.com](https://vercel.com) → **Add New** → **Project**.
2. Import your GitHub repo.
3. Configure:
   - **Framework Preset:** Vite
   - **Root Directory:** `client`
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
4. **Environment Variables:**

| Name | Value |
|------|-------|
| `VITE_API_URL` | `https://remarket-api.onrender.com/api` |

5. Click **Deploy**.
6. Note your frontend URL: `https://remarket-xxxx.vercel.app`

---

## Step 5 — Connect Frontend ↔ Backend

1. **Render** → your API service → **Environment**:
   - Update `CLIENT_URL` to your Vercel URL:
     ```
     CLIENT_URL=https://remarket-xxxx.vercel.app
     ```
   - For multiple domains (custom domain + vercel.app):
     ```
     CLIENT_URL=https://remarket-xxxx.vercel.app,https://yourdomain.com
     ```
2. **Manual Deploy** on Render to apply the change (or wait for auto-redeploy).
3. Test login at your Vercel URL with demo credentials (after seeding):
   - `rahul@remarket.demo` / `Demo@123`

---

## Step 6 — Custom Domain (optional)

### Vercel (frontend)
1. **Project Settings** → **Domains** → add `yourdomain.com`.
2. Add the DNS records Vercel shows (usually a CNAME).

### Render (API)
1. **Settings** → **Custom Domains** → add `api.yourdomain.com`.
2. Add the CNAME record Render provides.

### Update env vars after custom domain
- Render `CLIENT_URL`: `https://yourdomain.com,https://www.yourdomain.com`
- Vercel `VITE_API_URL`: `https://api.yourdomain.com/api`

## Environment Variable Reference

### Render (server)

See `server/.env.production.example` for the full list.

| Variable | Required | Notes |
|----------|----------|-------|
| `MONGO_URI` | Yes | Atlas connection string |
| `JWT_SECRET` | Yes | Min 32 chars |
| `JWT_REFRESH_SECRET` | Yes | Min 32 chars |
| `CLIENT_URL` | Yes | Vercel URL(s), comma-separated |
| `COOKIE_SAME_SITE` | Yes | `none` for cross-domain |
| `CLOUDINARY_*` | Yes | Images won't persist without this |
| `SMTP_*` | Yes | Email verification in production |

### Vercel (client)

| Variable | Required | Notes |
|----------|----------|-------|
| `VITE_API_URL` | Yes | `https://your-api.onrender.com/api` |

## Troubleshooting

### CORS error in browser
- `CLIENT_URL` on Render must exactly match your Vercel URL (no trailing slash).
- Redeploy Render after changing `CLIENT_URL`.

### Login works locally but not on Vercel
- Cookies need `COOKIE_SAME_SITE=none` and HTTPS (both platforms provide this).
- `withCredentials: true` is already set in `client/src/services/api.js`.
- Check DevTools → Application → Cookies — `accessToken` should appear after login.

### Images not loading
- Set all three `CLOUDINARY_*` vars on Render.
- Health check should show `"storage": "cloudinary"`.

### Render free tier sleeps after 15 min
- First request after sleep takes ~30–60 seconds (cold start).
- Upgrade to a paid plan or use a keep-alive ping service for demos.

### Email verification links go to localhost
- `CLIENT_URL` must be your Vercel URL, not `http://localhost:5173`.

### 503 on `/api/health`
- Check `MONGO_URI` — password special chars must be URL-encoded.
- Confirm Atlas Network Access allows `0.0.0.0/0`.
